# ورک‌فلو — راهنمای فارسی ساخت محصول جدید فول‌استک

از درخواست مشتری تا تصمیم مستند ورود به توسعه. راهنما فعلاً آموزش و کارگاه فازهای صفر تا دو را پیاده‌سازی می‌کند؛ مقصد کلی توسعه، انتشار و تحویل دیده می‌شود.

| فاز | مأموریت | خروجی |
| --- | --- | --- |
| [صفر](phases/phase-0.html) | فهم درخواست و حدود بررسی | نتیجهٔ مطلوب، محدودیت، مجوز و گام بعدی |
| [یک](phases/phase-1.html) | کشف مسئله و تعیین MVP کامل | گزینه‌ها، محدوده و خارج محدوده، تصمیم کارفرما، معیار و ریسک |
| [دو](phases/phase-2.html) | طراحی، ساخت و ارزیابی نمونه | تعریف رفتار MVP، نمونه و سورس، شواهد و تصمیم پایان |

هر فاز دو فرمان در صفحهٔ کارگاه دارد: شروع گفتگو و جمع‌بندی همان سشن. در فاز دو همان مشاور طراحی، پرامپت ابزار ساخت و اصلاح و چرخهٔ ارزیابی را هدایت می‌کند؛ پرامپت ساخت در جریان فرمان اول داده می‌شود و منتظر سند نهایی نیست. فرمان دوم پس از ارزیابی یا توقف است.

## بستهٔ مرجع و شواهد

یک بستهٔ مرجع محصول به‌تدریج کامل می‌شود. نسخه، مرحله، منابع، فرضیات، تصمیم معتبر و جایگزین‌شده، محدوده، رفتار، مجوزها و نتایج ارزیابی در آن روشن‌اند. توسعه‌دهنده نسخهٔ معتبر و ضمیمه‌های ضروری را نگهداری و برای سشن تازه منتقل می‌کند؛ سایت ذخیره و همگام‌سازی نمی‌کند. ارجاع‌ها معنایی و شناسه‌های FLOW / SCREEN / INT / AC پایدارند.

تأیید فهم توسعه‌دهنده، تصمیم کارفرما، پذیرش ریسک، توافق مالی و مجوز بررسی، ابزار، توسعه و انتشار مستقل‌اند. بررسی محدود واقعاً مجاز در همان حدود ممکن است. مثال پیوستهٔ TaskFlow آموزشی است؛ هیچ پاسخ یا تأیید آن شاهد واقعی نیست. راهنمای Replit تجربی و Stitch آزمایش‌نشده باقی می‌ماند.

پروتوتایپ فقط فرانت‌اند بدون بک‌اند است؛ سرور، دیتابیس، احراز هویت، پرداخت و ارسال واقعی درخواست نمی‌شود. حالت‌ها و داده‌ها صریحاً نمایشی‌اند. برای هر سناریو انتظار، مشاهده، نسخه، شاهد و Passed / Failed / Blocked / Not Tested ثبت می‌شود.

## تحویل توسعه

چهار وضعیت پایان: آمادهٔ توسعه، آمادهٔ توسعه با شرط مشخص، نیازمند بازنگری یا توقف. آمادگی به محدودهٔ تأییدشده، شواهد لازم، دسترسی به سورس و نبود ابهام بنیادی وابسته است. ادامهٔ مشروط نیازمند ثبت اثر کمبود، ریسک، پیگیری و تصمیم واقعی کارفرماست.

تعریف رفتار MVP مرجع درستی تست‌های آینده است، نه رفتار فعلی سورس. سورس قابل اصلاح یا بازسازی است؛ مقصد فول‌استک monorepo و سازمان‌دهی فرانت مانند feature-based الزامی است. to-spec برای spec، to-tickets برای تیکت‌بندی، implement یا implement-spec برای اجرا و wayfinder برای مسیر نامعلوم چندجلسه‌ای است؛ حجم زیاد به‌تنهایی دلیل wayfinder نیست. ترتیب تفصیلی مراحل بعد در این نسخه تثبیت نمی‌شود.

## ساختار و اجرا

HTML معنایی فارسی و RTL، CSS مشترک، بدون framework یا build. `assets/prompt.js` ورود، پیش‌نمایش و کپی همهٔ کارگاه‌ها و مرکز پروتوتایپ را انجام می‌دهد؛ `assets/phase-0-navigation.js` فهرست تعاملی را مدیریت می‌کند. ورودی ذخیره یا ارسال نمی‌شود؛ انتقال به LLM بیرونی تصمیم جداگانهٔ توسعه‌دهنده است.

از ریشهٔ مخزن اجرا کنید:

```sh
python3 -m http.server 8000
```

سپس [صفحهٔ آغاز](http://localhost:8000/phases/phase-0.html) را باز کنید. نصب وابستگی لازم نیست؛ تنظیم typecheck یا مجموعهٔ تست خودکار موجود نیست. هیچ framework تست تازه اضافه نشده است.
