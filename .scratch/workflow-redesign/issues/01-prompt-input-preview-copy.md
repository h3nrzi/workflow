# 01: ورود، پیش‌نمایش و کپی دقیق متن در کارگاه‌ها

**What to build:** توسعه‌دهنده بتواند در تمام کارگاه‌های صفر تا دو و مرکز پروتوتایپ، متن پروژه یا بستهٔ مرجع محصول را وارد کند، پرامپت کامل را ببیند و همان متن را با کپی خودکار یا دستی منتقل کند.

**Blocked by:** None (can start immediately)

**Status:** needs-info

**Implementation:** complete

**Evaluation:** preflight-complete

**Human acceptance:** pending

- [x] متن فارسی چندخطی، فاصله‌های ابتدا و انتها و نویسه‌های خاص، از جمله متن شبیه HTML، JavaScript و الگوهای جایگزینی، عیناً در پیش‌نمایش و متن کپی‌شده حفظ شوند؛ ورودی به‌عنوان کد یا نشانه‌گذاری تفسیر نشود.
- [x] پرامپت شروع از ورودی استفاده کند؛ فرمان جمع‌بندی با تغییر ورودی ثابت بماند و فقط به گفت‌وگوی همان سشن ارجاع دهد. ورودی خالی اطلاعات پروژه یا تأیید ساختگی نسازد.
- [x] پیام موفقیت فقط پس از موفقیت واقعی کپی نمایش داده شود؛ در شکست دسترسی Clipboard، پیش‌نمایش باز و متن برای انتخاب و کپی دستی در دسترس باشد.
- [x] ورودی ذخیره یا ارسال نشود؛ استفاده از LLM بیرونی اقدامی جدا و با تصمیم توسعه‌دهنده معرفی شود.
- [x] فرم‌ها برچسب و وضعیت قابل خواندن داشته باشند؛ پیش‌نمایش، کپی، فوکوس و بازیابی دستی در RTL، عرض باریک و با صفحه‌کلید قابل استفاده باشند.
- [x] رفتار بیرونی با ورودی خالی، فارسی چندخطی و نویسه‌های خاص، کپی موفق و کپی ناموفق بررسی شود؛ نتیجهٔ واقعی و موارد اجرا‌نشده ثبت شوند.
- [x] پس از پیاده‌سازی، بررسی‌های متناسب و code review انجام شوند؛ در همین چت راهنمای ارزیابی قابلیت‌های این تیکت با ورودی، اقدام، انتظار، checkpoint، شواهد واقعی preflight و نخستین اقدام کاربر ارائه شود. موارد اجرا‌نشده و پذیرش انسانی تا گزارش کاربر pending بمانند؛ این وضعیت مانع تکمیل پیاده‌سازی مجاز نیست.

## Comments

### ۲۰۲۶-۱۰-۲۷ — وضعیت پس از پیاده‌سازی و بازبینی

ورود عین‌به‌عین متن، استقلال فرمان دوم، کپی موفق و بازیابی دستی بررسی شدند. شکست Clipboard با خطای کنترل‌شده آزموده شد؛ رد واقعی مجوز سیستم هنوز تأیید نشده است.

- کامیت‌های پیاده‌سازی: `9f635c5` و `50926aa`.
- بازبینی Standards: یک ایراد سربرگ یافت و اصلاح شد. بازبینی مستقل Spec: صفر ایراد قابل اقدام.
- [راهنمای ارزیابی و شواهد هر تیکت](../../../docs/workflow-redesign-evaluation.md): ورودی، اقدام، انتظار، checkpoint، شواهد واقعی و نخستین اقدام کاربر ثبت شده‌اند.
- `needs-info` در اینجا یعنی انتظار گزارش مشاهدات ارزیاب برای پذیرش انسانی؛ پیاده‌سازی تکمیل شده و این وضعیت مانع تکمیل آن نیست. چک‌مارک‌های بالا بیانگر پیاده‌سازی/بررسی ثبت‌شده‌اند، نه پذیرش انسانی یا تضمین رفتار LLM.
- اقدام بعدی: checkpoint همین تیکت را طبق راهنما اجرا و مشاهده، انتظار و شاهد را گزارش کن. اجرای واقعی LLM بیرونی و پذیرش انسانی تا ثبت نتیجه pending می‌مانند.
