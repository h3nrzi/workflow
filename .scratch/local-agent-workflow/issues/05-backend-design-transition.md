# 05: ورود به فاز ۳ جدید — طراحی بک‌اند

**What to build:** خوانندهٔ نسخهٔ جدید از قرارداد خروج چرخهٔ فرانت به آموزش و کارگاه فاز ۳ طراحی بک‌اند برسد؛ بتواند قراردادهای لازم را آماده کند و مرز طراحی و ساخت واقعی را تشخیص دهد. محتوای فاز ۶ قبلی با هویت و ارجاع جدید قابل استفاده شود.

**Blocked by:** 01 — ورود به نسخهٔ جدید و حفظ ارجاع‌های قدیمی.

**Status:** ready-for-agent

- [ ] آموزش و کارگاه طراحی بک‌اند با شماره، عنوان، ناوبری و checkpoint نسخهٔ جدید عرضه شوند؛ ورود از مسیر جدید و مراجعه از ارجاع قدیمی به مقصد روشن و غیرمبهم برسند.
- [ ] ورودی از قرارداد مصوب خروج فاز ۲ شامل رفتار MVP، جریان‌ها، مرز داده و شبیه‌سازی، تست‌ها، شواهد و مسائل باز باشد؛ نبود تیکت‌های تکمیل‌شدهٔ کارگاه فرانت مانع تدوین این محتوای معلوم از طرح نباشد.
- [ ] مدل دامنه و داده، قرارداد عملیات و خطاها، احراز هویت و دسترسی، سرویس‌ها، استک و استقرار از نیاز واقعی محصول طراحی شوند؛ شکل موقت mock یا بک‌اند تولیدشدهٔ ابزار الزام معماری تلقی نشود.
- [ ] محتوای لازم فاز قبلی و تصمیم‌های سازگار دربارهٔ زبان، monorepo و مهارت همراه حفظ و با شمارهٔ جدید هم‌تراز شوند؛ تغییر نگاشت مهارت‌ها یا معماری محصول بی‌دلیل وارد دامنه نشود.
- [ ] شروع نقشه با پایان طراحی یا مجوز ساخت بک‌اند یکی نباشد. تصمیم مانع spec باز نماند؛ اجرای این فاز تکمیل و بررسی قراردادها و اسناد باشد و ساخت واقعی متعلق به فاز ۴ جدید باقی بماند.
- [ ] خروجی شامل قراردادهای قابل اجرا، تغییرات لازم فرانت، مرز تست و برنامهٔ اولین جریان متصل باشد و ورودی روشن فاز ۴ را فراهم کند؛ مسائل باز و حدود شواهد صریح بمانند.
- [ ] آموزش هدف، روش، مثال پیوسته، شکست، معیار پایان و تحویل داشته باشد. مثال و نتایج قبلی به اجرای واقعی نسخهٔ جدید یا محصول مشتری تبدیل نشوند.
- [ ] فرمان‌های معتبر این مرحله با ورودی، پیش‌نمایش و کپی مستقل کار کنند؛ متن فارسی چندخطی و نویسه‌های خاص، مسیر شکست کپی، لینک‌ها و fragmentهای متأثر، صفحه‌کلید و عرض‌های لازم بررسی شوند.
