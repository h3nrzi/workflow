# 01: ورود به نسخهٔ جدید و حفظ ارجاع‌های قدیمی

**What to build:** خواننده بتواند نسخهٔ جدید شش‌فازی ورک‌فلو را از مسیر قبلی تشخیص دهد، نگاشت مراحل را ببیند و لینک یا checkpoint قدیمی را بدون تغییر معنای پنهانی دنبال کند. مسیر جدید ابتدا کنار مسیر موجود اضافه می‌شود تا انتقال تدریجی محتوا، راهنمای فعلی را از کار نیندازد.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] مطابق طرح تأییدشده و ADR-0001، ورودی قابل مشاهدهٔ نسخهٔ جدید، نقشهٔ فازهای ۰ تا ۵ و نسبت آن‌ها با فازهای قبلی ارائه شود. بخش آماده‌نشده صریحاً آماده‌نشده معرفی شود و لینک شکسته یا ادعای تکمیل نداشته باشد.
- [ ] راهبرد آدرس‌دهی و انتقال پیاده شود تا نسخهٔ قدیم و جدید موقتاً کنار هم قابل استفاده باشند؛ شمارهٔ فاز مشترک باعث نمایش بی‌توضیح موضوع متفاوت نشود. بازآرایی زیرساختی فقط در حد لازم برای این سازگاری انجام شود.
- [ ] از یک لینک قدیمی آموزش و یک لینک قدیمی کارگاه بتوان به محتوای مربوط یا توضیح انتقال با مقصد روشن رسید. راهبرد حفظ یا نگاشت fragmentهای قدیمی مشخص و برای نمونه‌های متأثر بررسی شود.
- [ ] نسخهٔ ورک‌فلو و نگاشت checkpointهای قدیمی و جدید روشن باشد؛ CP-3 قدیمی با CP-3 جدید اشتباه نشود و شناسه‌های FLOW / SCREEN / INT / AC / DEC / TEST / OPEN به مفهوم دیگری تخصیص نیابند.
- [ ] قرارداد ورودی و خروجی مراحل جدید بر اساس طرح تأییدشده در دسترس باشد تا انتقال فاز طراحی بک‌اند بتواند مستقل از تکمیل کارگاه فرانت پیش برود. قرارداد شواهد، مرجع معتبر و معنای آماده/آماده‌نشده واحد باشد.
- [ ] مسیر فعلی تا زمان فعال‌سازی نهایی کار کند؛ سوابق طراحی و شواهد تاریخی بازنویسی یا به نتیجهٔ نسخهٔ جدید تبدیل نشوند. مسیر اصلی سایت در این تیکت کامل‌شده معرفی نشود.
- [ ] ناوبری و لینک‌های داخلی و fragmentهای متأثر بررسی شوند؛ ورودی و توضیح انتقال در موبایل و دسکتاپ و با صفحه‌کلید قابل استفاده باشند. نتیجهٔ انجام‌نشده صریح ثبت شود.
- [ ] بررسی‌های متناسب و code review انجام و پیش از تحویل در همان چت، راهنمای ارزیابی رفتارهای این تیکت با پیش‌شرط، اقدام، انتظار، شاهد واقعی preflight و نخستین اقدام کاربر ارائه شود؛ پذیرش انسانی تا گزارش مشاهده pending بماند.
