# 02: از بستهٔ فاز یک تا برنامهٔ ساخت فرانت

**What to build:** توسعه‌دهنده از بستهٔ مرجع محصول پایان فاز ۱ به آموزش و فرمان «شروع و طراحی» فاز ۲ جدید برسد؛ ایجنت بتواند ورودی‌ها و دارایی‌های موجود را بررسی کند و به برنامهٔ قابل بررسی برای چرخهٔ ساخت و ارزیابی فرانت برسد. این مسیر با سورس موجود و بدون سورس قابل استفاده باشد.

**Blocked by:** 01 — ورود به نسخهٔ جدید و حفظ ارجاع‌های قدیمی.

**Status:** ready-for-agent

**Resolution:** resolved (technical implementation)

**Human acceptance:** pending

- [x] آموزش هدف، ورودی، روش، مثال پیوسته، حالت شکست و معیار پایان طراحی را توضیح دهد و بدون LLM نیز قابل استفاده باشد؛ نقش ایجنت در کشف فنی و نقش انسان در تصمیم محصول روشن باشد.
- [x] خواننده بتواند از بستهٔ فاز ۱ به شروع طراحی نسخهٔ جدید برسد؛ فرمان مستقل ورودی لازم، خواندن دستورالعمل‌ها و اسناد معتبر و بررسی دسترسی سورس، ترمینال و مرورگر را پوشش دهد. نبود داده یا اختیار با فرض پنهانی پر نشود.
- [x] هر دو شاخهٔ «سورس در دسترس و قابل ارزیابی» و «نداشتن سورس نمونه» توضیح داده شوند؛ حفظ، اصلاح یا بازسازی مستدل باشد و نمونهٔ بدون سورس فقط در حد شواهد قابل‌دسترسی مرجع طراحی محسوب شود. ابزار بیرونی شرط ورود نباشد.
- [x] طراحی شامل رفتار MVP، نقشهٔ جریان‌ها و حالت‌های مهم، سناریوهای پذیرش، انتخاب مستدل فناوری فرانت، حداقل ساختار، مالکیت state، مرز داده، جهت بصری و واکنش‌گرایی و انتخاب جریان نماینده باشد. فناوری ثابت یا درخت پوشهٔ یکسان به همهٔ محصولات تحمیل نشود.
- [x] هر جریان پوشش مرورگری و قواعد پرترکیب تست منطق متناسب داشته باشند؛ انتظار از تعریف رفتار مصوب بیاید. تصمیم‌های سازگار پیشین دربارهٔ زبان و مقصد monorepo حفظ شوند؛ backend یا قرارداد نهایی API زودهنگام تحمیل نشود.
- [x] spec و واحدهای کار مبتنی بر جریان خروجی خود برنامه‌ریزی باشند و تولید هرکدام فرمان یا تأیید جدا نخواهد. فرمان طراحی اختیار ساخت محصول ایجاد نکند و ابهام مانع یک جریان از کار آمادهٔ مستقل جدا شود.
- [x] فرمان پیش‌نمایش و کپی قابل استفاده با ورودی فارسی چندخطی و نویسه‌های خاص داشته باشد؛ ورودی به‌عنوان متن حفظ شود، ذخیره یا ارسال یا اجرا نشود و مسیر کپی دستی هنگام شکست در دسترس باشد.
- [x] محل معتبر وضعیت و اسناد از فاز ۲ معرفی شود تا فرمان‌های بعدی به چت قبلی وابسته نباشند. شناسه‌های محصول حفظ و مثال آموزشی از شاهد واقعی جدا شود.
- [x] بررسی محتوایی و مرورگری متناسب، ناوبری، صفحه‌کلید و عرض‌های دسکتاپ، تبلت و موبایل انجام و code review ثبت شود. پیش از تحویل، راهنمای ارزیابی همین تیکت، شواهد واقعی preflight و نخستین اقدام کاربر در همان چت ارائه شود؛ پذیرش انسانی pending بماند.
