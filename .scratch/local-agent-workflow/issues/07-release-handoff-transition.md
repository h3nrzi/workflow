**What to build:** خواننده پس از تکمیل مسیر اتصال به آموزش و کارگاه انتشار، بازیابی، بازگشت نسخه و تحویل مسئولیت برسد. محتوای فاز ۸ قبلی با شماره‌گذاری جدید و حفظ معنای شواهد تاریخی قابل استفاده شود.

**Blocked by:** 06 — ورود به فاز ۴ جدید — اتصال واقعی.

**Status:** ready-for-agent

**Resolution:** resolved (technical implementation)

**Human acceptance:** pending

- [x] آموزش و کارگاه انتشار با عنوان، ناوبری، ارجاع و checkpoint نسخهٔ جدید عرضه شوند؛ مراجعه از مسیر جدید یا لینک قدیمی به محتوای مربوط با توضیح روشن برسد.
- [x] ورودی از خروج فاز ۴ جدید شامل نسخهٔ محصول متصل، رفتارهای اصلی، شواهد، مسائل باز و اختیار انتشار باشد؛ طراحی، مجوز انتشار و اجرای واقعی از هم قابل تشخیص باشند.
- [x] تصمیم‌ها و برنامهٔ اجرا محیط‌ها، secrets، دامنه و HTTPS، CI/CD، migration، backup و آزمون بازیابی، پایش، log و اعلام خطا را متناسب با محصول پوشش دهند؛ مورد نامرتبط دلیل عدم کاربرد داشته باشد.
- [x] بازگشت نسخه اثر تغییر دیتابیس را لحاظ کند؛ بالا آمدن سایت یا برگشت کد به‌تنهایی موفقیت انتشار و بازیابی محسوب نشود. بررسی جریان‌های اصلی در محیط واقعی و شاهد لازم آن توضیح داده شود.
- [x] تحویل شامل مسئول عملیات، دسترسی‌های لازم، راهنمای انتشار و رفع اشکال و حدود و مدت پشتیبانی توافق‌شده باشد؛ برنامهٔ توسعهٔ نسخه‌های آینده بی‌دلیل وارد دامنه نشود.
- [x] محتوای معتبر و مهارت همراه فاز قبلی با نگاشت جدید حفظ شوند؛ روش، مثال، شکست، معیار پایان و اقدام بعدی روشن باشد. سوابق قدیمی به‌عنوان شاهد انتشار نسخهٔ جدید بازنویسی نشوند.
- [x] فرمان‌های مرحله با ورودی، پیش‌نمایش و کپی مستقل، متن چندخطی و نویسه‌های خاص و مسیر شکست کپی قابل استفاده باشند؛ لینک‌ها، fragmentها، صفحه‌کلید و نمایش در عرض‌های لازم بررسی شوند.
- [x] بررسی‌های متناسب و code review انجام و در همان چت راهنمای ارزیابی این تیکت، شواهد واقعی preflight و نخستین اقدام کاربر ارائه شود؛ پذیرش انسانی pending بماند. انتشار سایت راهنما یا محصول مشتری و ایجاد تعهد مالی جزو اجرای این تیکت نباشد.
