# 03: از برنامهٔ مصوب تا ساخت و آزمون جریان‌ها

**What to build:** خواننده پس از طراحی بتواند فرمان اجرا را بررسی و کپی کند و بداند ایجنت چگونه ابتدا یک جریان نماینده را برای بازخورد بصری آماده می‌کند و سپس جریان‌های آماده را همراه تست، اصلاح و ثبت شاهد ادامه می‌دهد. این تیکت آموزش و فرمان اجرای محصول را می‌سازد، نه خود محصول مشتری را.

**Blocked by:** 02 — از بستهٔ فاز یک تا برنامهٔ ساخت فرانت.

**Status:** ready-for-agent

**Resolution:** resolved (technical implementation)

**Human acceptance:** pending

- [x] آموزش و فرمان اجرای مستقل از خروجی طراحی به ساخت جریان نماینده و سپس ادامهٔ جریان‌های آماده برسند. واحد کار هدف کامل کاربر باشد و طراحی حالت‌ها، پیاده‌سازی، تست و ثبت شاهد در همان واحد قرار گیرند.
- [x] انسان پیش از گسترش جهت بصری بتواند ظاهر، تعامل و واکنش‌گرایی جریان نماینده را با اقدام مشخص بررسی کند؛ کارهای مستقل مجاز در زمان انتظار ادامه یابند و پس از ثبت بازخورد، تأیید جداگانهٔ هر صفحه لازم نباشد.
- [x] اختیار فرمان اجرا و حدود آن روشن باشد: ایجنت برای هر تیکت اجازهٔ مجدد نخواهد، اما تصمیم تازهٔ رفتار محصول، تغییر محدوده یا دسترسی و هزینهٔ تازه به صاحب اختیار ارجاع شود. مسدودشدن یک جریان کار مستقل را متوقف نکند.
- [x] مرز فرانت بدون بک‌اند واقعی در آموزش و فرمان صریح باشد؛ داده و پاسخ‌ها شبیه‌سازی کنترل‌پذیر داشته باشند و احراز هویت، پرداخت، ارسال و ذخیره‌سازی سمت سرور واقعی این مرحله معرفی نشوند.
- [x] بررسی سورس، ترمینال، خطاها و رفتار مرورگر بر عهدهٔ ایجنت باشد؛ ارجاع بررسی فنی به توسعه‌دهنده به مانع واقعیِ ثبت‌شدهٔ دسترسی نیاز داشته باشد. نمونهٔ نبود دسترسی با اثر و راه پیگیری پوشش داده شود.
- [x] تست مرورگری هر جریان و تست منطق متناسب همراه ساخت پیش بروند؛ اختلاف پیاده‌سازی اصلاح و ابهام رفتار به تصمیم محصول برگردد. انتظار تست برای سبزشدن پنهانی تغییر نکند و mock اثبات امنیت یا صحت سرویس واقعی تلقی نشود.
- [x] ساختار featureها، مالکیت state و جداسازی داده و mock به‌اندازهٔ نیاز تکامل یابند. محتوای لازم مهاجرت، E2E و ریفکتور قدیم در همین مسیر ادغام شود؛ مهاجرت یا بازنویسی ساختار فقط با نیاز مشخص و بررسی حفظ رفتار انجام شود.
- [x] نسخه و محیط، پیش‌شرط، اقدام، انتظار، مشاهده و شاهد هر بررسی با Passed / Failed / Blocked / Not Tested ثبت شوند؛ وضعیت مخزن و اقدام بعدی پس از هر واحد به‌روز شود.
- [x] پیش‌نمایش و کپی فرمان اجرا از ورودی فرمان طراحی مستقل باشند؛ متن فارسی و نویسه‌های خاص عیناً منتقل شوند و کپی ناموفق مسیر دستی داشته باشد. ناوبری، صفحه‌کلید و نمایش در عرض‌های لازم بررسی شوند.
- [x] بررسی‌های متناسب و code review ثبت و در همان چت راهنمای ارزیابی قابلیت‌های این تیکت، شواهد واقعی preflight و نخستین اقدام کاربر ارائه شود؛ پذیرش انسانی pending بماند و ساخت محصول مشتری از مثال آموزشی استنتاج نشود.
