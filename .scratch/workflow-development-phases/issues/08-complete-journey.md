# 08: یکپارچه‌سازی مسیر صفر تا هشت و ارزیابی سراسری

**What to build:** خواننده از نمای کلی و ناوبری راهنما، مسیر پیوستهٔ صفر تا هشت را پیدا و از تحویل پروتوتایپ تا آموزش و فرمان‌های تحویل نهایی طی کند. اتصال صفحات، مستندات فعال، مثال و checkpointهای بستهٔ مرجع یکپارچه و نقص‌های سراسری رفع شوند؛ شواهد این نسخه مستقل از سوابق قبلی ثبت شوند.

**Blocked by:** 01 — اصلاح مسیر ساخت پروتوتایپ و تحویل فاز دو؛ 02 — تکمیل آموزش و کارگاه فاز سه: تحویل‌گیری و مهاجرت؛ 03 — تکمیل آموزش و کارگاه فاز چهار: E2E و اصلاح رفتار MVP؛ 04 — تکمیل آموزش و کارگاه فاز پنج: ریفکتور فرانت؛ 05 — تکمیل آموزش و کارگاه فاز شش: طراحی بک‌اند؛ 06 — تکمیل آموزش و کارگاه فاز هفت: توسعه و اتصال تدریجی؛ 07 — تکمیل آموزش و کارگاه فاز هشت: انتشار و تحویل.

**Status:** needs-info

- [x] نمای کلی، ناوبری، دسترسی آموزش و کارگاه‌ها، اقدام قبل و بعد هر فاز و مستندات پشتیبان فعال با دامنهٔ صفر تا هشت همسو شوند. محدودیت قدیمی «فقط معرفی مراحل بعدی» از قرارداد فعال برداشته شود؛ سوابق تاریخی تحریف نشوند و ارجاع فعال به مسیر ابزار صرفاً طراحی باقی نماند.
- [x] ماتریس پوشش، اصلاح فاز دو و هر شش فاز جدید را با spec تطبیق دهد: آموزش واقعی، ورودی و خروجی و شرط پایان، فرمان‌های کامل و مستقل، مرز طراحی و اجرا و پذیرش، مهارت‌های ثابت grill-with-docs برای ۳، ۴، ۵ و ۷ و wayfinder برای ۶ و ۸. نام مرحله یا ارجاع صرف به مهارت پوشش محسوب نشود؛ شکاف‌های کشف‌شده رفع شوند.
- [x] مثال پیوستهٔ TaskFlow از بستهٔ فاز دو تا پایان هشت دنبال شود؛ شناسه‌های رفتار، تصمیم‌ها، وضعیت تست و مسائل باز بین checkpointها سازگار باشند. تغییر تصمیم، شواهد متأثر را برای بازبینی مشخص کند و مثال آموزشی با شاهد واقعی مخلوط نشود.
- [x] مسیر سشن تازه با خواندن اسناد معتبر مخزن روشن باشد؛ فقدان ورودی اختیاری، سند متعارض و ابهام هویت تیکت به جعل اطلاعات یا انتخاب دلخواه منجر نشوند. جمع‌بندی‌ها به همان مرجع معتبر ارجاع دهند و مرحلهٔ بعد را خودکار شروع نکنند.
- [x] شاخه‌های ضروری با محتوای قابل استفاده پوشش داشته باشند: فناوری و ساختار متفاوت سورس، سورس اجرا‌نشدنی، بک‌اند ناخواستهٔ ابزار، اختلاف با MVP، ابهام رفتار، تغییر بنیادی فناوری، تست اجرا‌نشده، تصمیم باز نقشه، تعارض سند و نقص مانع یا قابل انتقال. نقص‌های محتوایی و اتصال کشف‌شده رفع شوند.
- [x] مسیرها، fragmentها، headingها و شناسه‌های تکراری در کل سایت بررسی شوند. پیش‌نمایش و کپی تک‌تک فرمان‌ها، استقلال ورودی‌ها و فرمان‌های بدون ورودی، ورودی خالی و فارسی چندخطی، نویسه‌های خاص و متن شبیه HTML یا JavaScript بررسی شوند؛ متن عیناً منتقل شود و ذخیره، ارسال یا اجرا نشود.
- [x] کپی موفق با شاهد واقعی و مسیر شکست کنترل‌شده یا رد واقعی مجوز با برچسب دقیق ثبت شوند؛ شکست به انتخاب متن و کپی دستی برسد. صحت نحوی اسکریپت‌های متأثر و رگرسیون کارگاه‌های صفر تا دو بررسی و نقص‌ها رفع شوند.
- [x] ارزیابی بصری مستقل دسکتاپ، تبلت و موبایل و ارزیابی صفحه‌کلید شامل خوانایی RTL، فهرست‌ها، فوکوس، anchorها، پیش‌نمایش، جدول‌ها و نبود بریدگی محتوای مهم انجام شود؛ نبود overflow به‌تنهایی شاهد کیفیت بصری نباشد. هویت بصری موجود حفظ شود و framework، build، بک‌اند یا سامانهٔ تست تازه صرفاً برای این تغییر اضافه نشود.
- [x] بررسی متن پرامپت از اجرای واقعی آن در Agent جدا گزارش شود. هر اجرای واقعی ابزار یا محیط، ورودی، مراحل، مشاهده و شاهد داشته باشد؛ موارد انجام‌نشده pending یا Not Tested بمانند. ساخت و استقرار محصول واقعی مشتری یا برابری قطعی پاسخ LLM شرط پذیرش سایت نباشد.
- [x] پس از بررسی‌های متناسب و code review، راهنمای ارزیابی قابل تکرار feature-by-feature با ورودی، اقدام، انتظار، checkpoint، شاهد واقعی preflight و نخستین اقدام کاربر در همان چت آماده شود. پوشش و checkpointهای تک‌تک هشت تیکت حفظ شوند؛ نتایج قدیمی شاهد نسخهٔ تازه نشوند و پذیرش انسانی تا گزارش مشاهدات کاربر pending بماند. انتشار خود سایت، ایجاد حساب، خرید ابزار و ارسال پیام به دیگران انجام نشود.
