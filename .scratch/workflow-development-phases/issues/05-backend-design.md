# 05: تکمیل آموزش و کارگاه فاز شش: طراحی بک‌اند

**What to build:** توسعه‌دهنده با آموزش، مثال و فرمان‌های فاز شش از ایجاد نقشهٔ تصمیم تا قراردادهای اجرایی بک‌اند و ورودی روشن توسعهٔ جریان اول هدایت شود؛ مرز طراحی و ساخت بک‌اند در تمام مسیر معلوم بماند. محصول این تیکت سایت راهنماست، نه بک‌اند محصول مشتری.

**Blocked by:** 02 — تکمیل آموزش و کارگاه فاز سه: تحویل‌گیری و مهاجرت؛ برای قرارداد مشترک فرمان‌ها و checkpoint مثال. پیاده‌سازی آموزش به تکمیل صفحات فاز چهار و پنج وابستگی اجرایی ندارد.

**Status:** needs-info

- [x] آموزش برای هر فعالیت اصلی چرایی، ورودی، روش، مثال پیوستهٔ TaskFlow، شکست و بازگشت، خروجی خوب، شرط پایان و اقدام بعدی داشته باشد و بدون LLM نیز قابل استفاده باشد.
- [x] رفتار MVP، قواعد کسب‌وکار و نیاز واقعی فرانت مبنای مدل دامنه و داده، عملیات، خطاها، مجوزها و احراز هویت متناسب با محصول باشند؛ شکل موقت دادهٔ فرانت قرارداد اجباری بک‌اند نشود. تغییر داده، سرویس بیرونی، محیط، امنیت و کارایی در صورت ارتباط پوشش داده شوند.
- [x] گزینه‌های استک اپلیکیشن در JS/TS به انتخاب مستدل برسند؛ دیتابیس و زیرساخت محدودیت زبان نداشته باشند. مقصد استقرار با محدودیت واقعی پیش از نهایی‌شدن معماری انتخاب شود؛ مرز تست قواعد، تعامل API و دیتابیس و استفادهٔ دوباره از سناریوهای E2E روشن باشد.
- [x] برنامهٔ تغییر فرانت، تصمیم‌های لازم مدیریت دادهٔ سرور پیش از اجرای اتصال و ورودی جریان اول فرانت تا API و دیتابیس واقعی روشن شوند؛ ساخت کل بک‌اند قبل از اولین اتصال برنامهٔ پیش‌فرض نباشد.
- [x] شروع ثابت wayfinder فقط ایجاد نقشه و تیکت‌های تصمیم باشد. ادامهٔ نقشه فرمان مستقل داشته باشد و claim، انتخاب تیکت باز بدون مانع و بدون claim، پیشبرد فقط همان تصمیم در جلسه، پاسخ انسانی و ثبت پاسخ و ارجاع به محل معتبر را توضیح دهد؛ نقشه مرجع موازی نسازد.
- [x] ایجاد نقشه یا حل یک تصمیم پایان طراحی نباشد؛ تصمیم مانعِ تدوین spec باز نماند. مثال، تصمیم باز، سند متعارض و بازگشت به محل تصمیم معتبر را نشان دهد؛ ساخت واقعی بک‌اند به فاز هفت تعلق داشته باشد.
- [x] فرمان‌های مستقل و کامل شروع، ادامهٔ wayfinder، to-spec، to-tickets، implement-spec، implement تک‌تیکت و ارزیابی و جمع‌بندی مطابق متن‌های تأییدشده با پیش‌نمایش و کپی مستقل عرضه شوند. اجرای تیکت‌های فاز شش فقط تکمیل و بررسی قراردادها و اسناد باشد و مهارت‌ها هم‌زمان فعال نشوند.
- [x] Agent از پروژهٔ جاری اسناد را کشف کند؛ مسیر مخزن دستی نباشد و ورودی اختیاری برای همان فرمان باقی بماند. بستهٔ مرجع، تصمیم‌ها، تست‌ها و مسائل باز برای سشن تازه در مخزن قابل خواندن باشند. مثال آموزشی و شاهد واقعی جدا شوند؛ پایان طراحی، اجرای فاز و پذیرش انسانی مستقل باشند و انتقال نقص تصمیم، اثر، مسئول و زمان رسیدگی بخواهد.
- [x] پوشش محتوایی، مسیر و fragment، heading و شناسه، پیش‌نمایش و کپی تمام فرمان‌ها با ورودی خالی و فارسی چندخطی و نویسه‌های خاص، استقلال آن‌ها، شکست کپی و مسیر دستی، صفحه‌کلید و نمایش دسکتاپ، تبلت و موبایل بررسی شوند. پس از code review، راهنمای feature-by-feature با شاهد واقعی preflight، ورودی، اقدام، انتظار، checkpoint و نخستین اقدام کاربر در همان چت آماده شود؛ پذیرش انسانی pending بماند.
