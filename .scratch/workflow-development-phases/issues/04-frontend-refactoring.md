# 04: تکمیل آموزش و کارگاه فاز پنج: ریفکتور فرانت

**What to build:** توسعه‌دهنده در آموزش و کارگاه فاز پنج، بازآرایی feature-based متناسب با پروژه را با حفظ رفتار و جداسازی دسترسی به داده طراحی و دنبال کند؛ مثال پیوسته و فرمان‌های مستقل، خروجی قابل بررسی هر گام را روشن کنند. محصول این تیکت سایت راهنماست.

**Blocked by:** 02 — تکمیل آموزش و کارگاه فاز سه: تحویل‌گیری و مهاجرت؛ برای قرارداد مشترک فرمان‌ها و checkpoint مثال. آماده بودن صفحهٔ فاز چهار مانع پیاده‌سازی این آموزش نیست؛ پیش‌نیاز رفتاری فاز چهار در خود راهنما توضیح داده شود.

**Status:** needs-info

- [x] آموزش برای هر فعالیت اصلی چرایی، ورودی، روش اجرایی، مثال TaskFlow، شکست و بازگشت، خروجی خوب، شرط پایان و اقدام بعدی ارائه کند و بدون LLM نیز مفید باشد.
- [x] مرز featureها، بخش‌های مشترک، state و جهت وابستگی‌ها از نیاز واقعی پروژه استخراج شوند؛ درخت پوشهٔ ثابت تحمیل نشود. بازآرایی به گام‌های قابل بررسی با E2E و حفظ رفتار تقسیم شود؛ وجود فایل تست شاهد اجرای موفق آن نباشد.
- [x] جداسازی دسترسی به داده و شبیه‌سازی‌ها از اجزای رابط و محل جایگزینی با سرویس واقعی آموزش داده شود؛ اتصال واقعی در این فاز انجام نشود. انتخاب نهایی ابزار مدیریت دادهٔ سرور با شناخت API و پیش از اجرای اتصال در فاز هفت باقی بماند؛ تغییر ابزار دلیل و پوشش تست بخواهد.
- [x] تصمیم فناوری فرانت فاز سه حفظ شود و مانع تازه به بازنگری مستند آن برگردد؛ تغییر رفتار MVP یا تعویض پنهانی فناوری داخل ریفکتور پنهان نشود. مثال، رگرسیون و بازگشت به گام معتبر را نشان دهد.
- [x] شروع ثابت grill-with-docs و فرمان‌های مستقل to-spec، to-tickets، implement-spec، implement تک‌تیکت و ارزیابی و جمع‌بندی بر اساس متن‌های تأییدشده عرضه شوند؛ همه پیش‌نمایش و کپی مستقل داشته باشند و فرمان طراحی اجرای محصول را آغاز نکند.
- [x] پروژهٔ جاری و اسناد معتبر منبع باشند؛ مسیر مخزن ورودی دستی نباشد. ورودی اختیاری به فرمان مرتبط محدود شود، تعارض اسناد با حدس حل نشود و checkpoint بستهٔ مرجع برای سشن تازه شامل تصمیم‌ها، تست‌های اجراشده و مسائل باز باشد.
- [x] پایان طراحی، پایان اجرای فاز و پذیرش انسانی جدا باشند؛ نقص مانع و نقص قابل انتقال با تصمیم، اثر، مسئول و زمان رسیدگی معلوم شوند. امنیت، کارایی، دسترس‌پذیری و موبایل در جای مرتبط با معیار متناسب با MVP پوشش داده شوند و مثال آموزشی شاهد واقعی معرفی نشود.
- [x] محتوای فاز، لینک و fragment، heading و شناسه، پیش‌نمایش و کپی تک‌تک فرمان‌ها با ورودی خالی و متن فارسی چندخطی و خاص، استقلال ورودی‌ها، شکست کپی و مسیر دستی، صفحه‌کلید و نمایش دسکتاپ، تبلت و موبایل بررسی شوند. پس از code review، راهنمای feature-by-feature با شواهد واقعی preflight، ورودی، اقدام، انتظار، checkpoint و نخستین اقدام کاربر در همان چت آماده شود؛ پذیرش انسانی pending بماند.
