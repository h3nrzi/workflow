# 07: تکمیل آموزش و کارگاه فاز هشت: انتشار و تحویل

**What to build:** توسعه‌دهنده در سایت راهنما از نقشهٔ تصمیم انتشار تا برنامهٔ اجرایی متناسب با زیرساخت، ارزیابی محیط واقعی و تحویل به مسئول مشخص هدایت شود. آموزش، مثال و تمام فرمان‌های لازم قابل استفاده باشند؛ ساخت یا استقرار واقعی محصول مشتری و انتشار خود سایت راهنما موضوع این تیکت نیست.

**Blocked by:** 02 — تکمیل آموزش و کارگاه فاز سه: تحویل‌گیری و مهاجرت؛ برای قرارداد مشترک فرمان‌ها و checkpoint مثال. پیاده‌سازی صفحه به آماده بودن سایر صفحات جدید وابستگی اجرایی ندارد.

**Status:** needs-info

- [x] آموزش برای هر فعالیت اصلی چرایی، ورودی، روش قابل اجرای پروژه، مثال TaskFlow، شکست و بازگشت، خروجی خوب، شرط پایان و اقدام بعدی داشته باشد و بدون LLM نیز مفید باشد؛ فهرست اصطلاحات یا توصیهٔ عمومی جای راهنمای عملی متناسب با سورس و زیرساخت واقعی نباشد.
- [x] محیط‌ها و secrets، دامنه و HTTPS، بررسی‌ها و انتشار خودکار با CI/CD، migration، backup و آزمون بازیابی، log، پایش سلامت و اطلاع از خطا در تصمیم و اجرای برنامه پوشش داده شوند؛ هر مورد شاهد انجام یا دلیل روشن عدم کاربرد بخواهد.
- [x] بازگشت نسخه اثر تغییر دیتابیس را لحاظ کند؛ برگشت کد کافی فرض نشود. جریان‌های اصلی در محیط واقعی و امنیت، کارایی، دسترس‌پذیری و موبایل متناسب با MVP بررسی شوند؛ شواهد قبلی استفاده و شکاف‌ها مشخص شوند و بالا آمدن سایت پایان فاز نباشد.
- [x] مسئول عملیات، دسترسی‌های لازم، راهنمای انتشار و رفع اشکال، مسئول رسیدگی به خطاهای پس از انتشار و مدت و حدود پشتیبانی توافق‌شده جزو تحویل باشند؛ فرایند کامل نگهداری و نسخه‌های بعدی خارج از دامنه بماند.
- [x] شروع ثابت wayfinder فقط مقصد، نقشه و تیکت‌های تصمیم را بسازد؛ ادامهٔ مستقل، انتخاب و claim تیکت باز بدون مانع و بدون claim، پیشبرد همان تصمیم در جلسه، پاسخ انسانی و ثبت پاسخ و ارجاع معتبر را رعایت کند. تصمیم مانع برنامهٔ اجرایی باز نماند؛ ایجاد نقشه پایان طراحی یا تحویل معرفی نشود.
- [x] فرمان‌های مستقل شروع، ادامهٔ wayfinder، to-spec، to-tickets، implement-spec، implement تک‌تیکت و ارزیابی و جمع‌بندی مطابق متن‌های تأییدشده با پیش‌نمایش و کپی مستقل عرضه شوند؛ طراحی یا ادامهٔ نقشه انتشار ضمنی انجام ندهد و مهارت‌ها هم‌زمان فعال نشوند.
- [x] مثال آموزشی بازیابی ناموفق، اثر دیتابیس بر بازگشت نسخه و نقص مانع یا قابل انتقال را نشان دهد؛ انتقال نقص تصمیم، اثر، مسئول و زمان رسیدگی بخواهد. هیچ مثال به‌عنوان استقرار یا تحویل واقعی معرفی نشود و معیار عددی ساختگی برای همهٔ محصولات تحمیل نشود.
- [x] Agent از پروژهٔ جاری و اسناد معتبر استفاده کند و مسیر مخزن نخواهد؛ ورودی اختیاری فقط به فرمان مرتبط افزوده شود. بستهٔ مرجع، تصمیم‌ها، شواهد و مسائل باز برای سشن تازه قابل خواندن باشند و جمع‌بندی نسخهٔ متناقض نسازد. پایان طراحی، پایان اجرای فاز و پذیرش انسانی جدا بمانند.
- [x] پوشش محتوایی، لینک و fragment، heading و شناسه، پیش‌نمایش و کپی تمام فرمان‌ها با ورودی خالی و فارسی چندخطی و خاص، استقلال آن‌ها، شکست کپی و مسیر دستی، صفحه‌کلید و نمایش دسکتاپ، تبلت و موبایل بررسی شوند. پس از code review، راهنمای feature-by-feature با شاهد واقعی preflight، ورودی، اقدام، انتظار، checkpoint و نخستین اقدام کاربر در همان چت آماده شود؛ پذیرش انسانی pending بماند.
