# 06: تکمیل آموزش و کارگاه فاز هفت: توسعه و اتصال تدریجی

**What to build:** توسعه‌دهنده با آموزش و کارگاه فاز هفت بتواند ابتدا یک کار معنادار کاربر را در جریان کامل فرانت تا API و دیتابیس واقعی اثبات کند و سپس باقی جریان‌های MVP را گسترش دهد؛ مثال، فرمان‌های مستقل و معیارهای پایان، برنامهٔ اتصال را از شاهد اتصال واقعی جدا کنند. این تیکت خود راهنما را پیاده می‌کند.

**Blocked by:** 02 — تکمیل آموزش و کارگاه فاز سه: تحویل‌گیری و مهاجرت؛ برای قرارداد مشترک فرمان‌ها و checkpoint مثال. آماده بودن صفحهٔ طراحی بک‌اند مانع ساخت این آموزش نیست؛ پیش‌نیاز قراردادهای نهایی در خود راهنما صریح باشد.

**Status:** needs-info

- [x] هر فعالیت اصلی چرایی، پیش‌نیاز و ورودی، روش، مثال TaskFlow، شکست و بازگشت، معیار خروجی خوب، شرط پایان و اقدام بعدی داشته باشد؛ خواننده بدون LLM نیز مسیر را بفهمد.
- [x] جریان اول با ارزش کاربر و خطر اتصال انتخاب و دلیلش ثبت شود؛ باقی کار برش‌های کامل با وابستگی واقعی باشد. تکمیل تمام بک‌اند پیش از اولین اتصال برنامه‌ریزی نشود و پایان نقشهٔ طراحی به معنی ساخته‌شدن بک‌اند نباشد.
- [x] برای هر جریان تغییر فرانت، عملیات و دادهٔ واقعی، مجوزها، انتظار و خطا و تست مناسب روشن باشند. انتخاب نهایی ابزار دریافت و مدیریت دادهٔ سرور با شناخت API پیش از اجرای اتصال انجام شود؛ تغییر ابزار دلیل و پوشش تست داشته باشد. کد اپلیکیشن و ابزارهای مرتبط در اکوسیستم JS/TS باقی بمانند.
- [x] E2E با تست قواعد مهم کسب‌وکار و تعامل API و دیتابیس تکمیل شود؛ دسترسی، اعتبارسنجی، تغییر داده و شکست عملیات متناسب با ریسک پوشش داده شوند و تست همهٔ توابع داخلی الزام نشود. همان سناریوهای رفتاری روی محصول متصل اجرا شوند.
- [x] زمان جایگزینی هر شبیه‌سازی روشن باشد و پایان اتصال نبود اتکا به دادهٔ نمایشی یا موفقیت ساختگی در مسیر واقعی را بررسی کند. مثال آموزشی شکست اتصال و شبیه‌سازی باقی‌مانده را نشان دهد؛ موفقیت نمایشی شاهد محصول واقعی نشود.
- [x] ابهام معماری ضروری یا تعارض سورس با قراردادها به مانع و محل بازنگری مشخص برگردد؛ نیاز تازه و تغییر رفتار MVP تصمیم جدا بخواهند. امنیت، کارایی، دسترس‌پذیری و موبایل متناسب با جریان در این فاز بررسی شوند و همه به انتشار موکول نشوند.
- [x] شروع ثابت grill-with-docs و فرمان‌های مستقل to-spec، to-tickets، implement-spec، implement تک‌تیکت و ارزیابی و جمع‌بندی بر اساس متن‌های تأییدشده با پیش‌نمایش و کپی مستقل عرضه شوند؛ فرمان طراحی توسعه یا اتصال را آغاز نکند.
- [x] پروژهٔ جاری و اسناد معتبر منبع باشند و مسیر مخزن دستی نباشد؛ ورودی تکمیلی اختیاری فقط به فرمان مرتبط افزوده شود. checkpoint بستهٔ مرجع برای ورود به انتشار شامل تصمیم‌ها، تست‌ها و مسائل باز باشد؛ تعارض سند و ابهام تیکت با حدس حل نشوند. پایان طراحی، اجرای فاز و پذیرش انسانی جدا و نقص‌های قابل انتقال دارای تصمیم، اثر، مسئول و زمان رسیدگی باشند.
- [x] پوشش محتوایی، لینک و fragment، heading و شناسه، پیش‌نمایش و کپی تمام فرمان‌ها با ورودی خالی و فارسی چندخطی و خاص، استقلال آن‌ها، شکست کپی و مسیر دستی، صفحه‌کلید و نمایش دسکتاپ، تبلت و موبایل بررسی شوند. پس از code review، راهنمای feature-by-feature با شاهد واقعی preflight، ورودی، اقدام، انتظار، checkpoint و نخستین اقدام کاربر در همان چت آماده شود؛ پذیرش انسانی pending بماند.
