# 03: تکمیل آموزش و کارگاه فاز چهار: E2E و اصلاح رفتار MVP

**What to build:** توسعه‌دهنده در سایت راهنما از تعریف رفتار MVP تا طراحی پوشش همهٔ جریان‌ها، اجرای سناریوهای قابل مشاهده و اصلاح اختلاف رفتار هدایت شود؛ آموزش، کارگاه، مثال و فرمان‌های کامل همان فاز قابل استفاده باشند. این تیکت راهنمای تست محصول را می‌سازد و اجرای تست یک محصول واقعی مشتری موضوع آن نیست.

**Blocked by:** 02 — تکمیل آموزش و کارگاه فاز سه: تحویل‌گیری و مهاجرت؛ برای قرارداد مشترک فرمان‌ها و checkpoint مثال. ترتیب آموزشی، وابستگی اضافه‌ای برای پیاده‌سازی صفحات ایجاد نمی‌کند.

**Status:** needs-info

- [x] هر فعالیت اصلی چرایی، ورودی، روش اجرایی، مثال پیوستهٔ TaskFlow، شکست و بازگشت، معیار خروجی خوب، شرط پایان و اقدام بعدی داشته باشد؛ مطالعه بدون LLM نیز روش کار را روشن کند.
- [x] همهٔ جریان‌های داخل MVP و حالت‌های مهم خطا، دسترسی و دادهٔ خالی به سناریوهای قابل مشاهده مرتبط شوند. تعریف تأییدشدهٔ رفتار MVP مرجع باشد و تست رفتار اشتباه فعلی سورس را تثبیت نکند.
- [x] انتخاب ابزار E2E در اکوسیستم JS/TS، دادهٔ آزمون، جداسازی سناریوها و شبیه‌سازی صریح سرویس ساخته‌نشده بر اساس پروژه آموزش داده شود؛ کتابخانه یا ساختار سورس از پیش فرض نشود. شبیه‌سازی دسترسی اثبات امنیت بک‌اند معرفی نشود.
- [x] اختلاف پیاده‌سازی در همین فاز اصلاح و موارد خارج از MVP از مسیر نسخه کنار گذاشته شوند؛ نقص تعریف رفتار به تصمیم محصول بازگردد. Agent برای سبز کردن تست رفتار مطلوب را تغییر ندهد و ریفکتور معماری یا ساخت بک‌اند وارد این فاز نشود.
- [x] مثال، ارتباط رفتار و سناریو، انتظار، نتیجه، شاهد و وضعیت Passed / Failed / Blocked / Not Tested را نشان دهد؛ سناریوها برای اجرای بعدی روی محصول متصل قابل استفاده باشند و بی‌دلیل به ساختار داخلی فرانت وابسته نشوند. مثال و شواهد واقعی جدا برچسب بخورند.
- [x] شروع ثابت grill-with-docs و فرمان‌های جداگانهٔ to-spec، to-tickets، اجرای کل فاز با implement-spec، اجرای تک‌تیکت با implement و ارزیابی و جمع‌بندی مطابق متن‌های تأییدشده عرضه شوند؛ هرکدام پیش‌نمایش و کپی مستقل داشته باشد. شروع طراحی به اجرای تست یا اصلاح کد تبدیل نشود.
- [x] Agent از پروژهٔ جاری و اسناد معتبر استفاده کند و مسیر مخزن نخواهد؛ ورودی تکمیلی اختیاری و مختص فرمان باشد. سشن تازه، سند متعارض و ابهام رفتار بدون حدس پوشش داده شوند. بستهٔ مرجع، تصمیم‌ها و مسائل باز در محل معتبر به‌روز شوند.
- [x] پایان طراحی، اجرای فاز و پذیرش انسانی جدا باشند؛ نقص مانع و نقص قابل انتقال با تصمیم، اثر، مسئول و زمان رسیدگی معلوم باشند و امنیت، کارایی، دسترس‌پذیری و موبایل متناسب با ریسک در فاز مرتبط بررسی شوند.
- [x] پوشش محتوایی، لینک و fragment، heading و شناسه، پیش‌نمایش و کپی تمام فرمان‌ها با ورودی خالی و فارسی چندخطی و نویسه‌های خاص، استقلال فرمان‌ها، کپی دستی، صفحه‌کلید و نمایش دسکتاپ، تبلت و موبایل بررسی شوند. پس از code review، راهنمای feature-by-feature با شواهد واقعی preflight، ورودی، اقدام، انتظار، checkpoint و نخستین اقدام کاربر در همان چت آماده شود؛ پذیرش انسانی pending بماند.
